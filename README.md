# ARC White-Box Estimation Challenge 2026 — Phase 2 (AIcrowd)

Estimators, local tooling and every submission of team `koushik_rudra` for the
[ARC White-Box Estimation Challenge 2026](https://www.aicrowd.com/challenges/arc-white-box-estimation-challenge-2026).

**Task.** Given the weights of a random ReLU MLP (width 1024, depth 16, He init, Gaussian input), predict the
expected post-ReLU activation of every neuron in every layer. Score per MLP = final-layer MSE × max(0.1, C / 2^41),
where C is the FLOP count metered by `flopscope`; 0.4 s of participant-side Python time per MLP is allowed.

## Method (what we added on top of V29)

**Dead-unit pruning (V30–V34).** Neurons of each layer are relabelled by a cheap pre-estimate of
α = μ/σ (descending), so units that are almost never active (α ≪ 0, zero ReLU gain, no K3 read-out) are the
trailing indices. Every heavy product is then restricted to a prefix: `S_OUT[l]` rows of the K3 legs kept at layer
l (read-out side), `S_IN[l]` rows kept as the inner index of the transport out of layer l (gain side; legs are
w1-scaled there). The covariance product W·C stays exact (two small dense corrections), because pruning the
covariance itself costs +30% MSE. Result: −8% FLOPs at unchanged MSE (20-MLP local check).

**V37.** (i) The join of a source into the shared basis (randomized range finder, projections, rotation of the old
factors, basis transport W·Q, lift Q^T) runs as Strassen families with a rectangular leaf minimum instead of dense
products; (ii) Strassen sub-views of the pooled scratch buffers are created once and cached (a slice is a
client→server round trip under the grader's client/server flopscope, half of all calls); (iii) the final layer only
needs D3, so its K3 legs keep a row band (128 most saturated + 128 most dead units dropped); (iv) thin legs are
transported on the live block only.

## Layout

| path | content |
|---|---|
| `est/` | estimator versions (`v29.py` = upstream V29; `v34.py` = submission 333482; `v37.py` = current) |
| `submissions/` | every submitted file + grading metadata (auto-generated by `tools/submit.py`) |
| `tools/run_est.py` | grader-style local runner (C/B, MSE vs 1e9-sample truth, residual, ops, peak memory) |
| `tools/sweep.py` | parallel configuration sweeps → `runs/sweep.jsonl` |
| `tools/audit.py`, `tools/mk_audit.py` | per-family FLOP ledger of one predict |
| `tools/submit.py` | validate → package → submit → watch → record → push |
| `tools/gh.py` | stdlib GitHub client used for the pushes (token read from the user profile, never from the repo) |
| `cs/` | client/server harness reproducing the grader's `flopscope-client` ↔ `flopscope-server` setup |
| `runs/` | sweep configs, results log, ledgers |

## Reproducing

1. `whest-starterkit` environment (`flopscope==0.12.1`, `whestbench==0.16.1`), Python 3.11.
2. Ground truth: the public `mini` split parquet shards → `tools/pq2npz.py` → `data/npz/mlp_XXXX.npz`.
3. `python tools/run_est.py --est est/v37.py --ids 96,97 --warm 1`.
